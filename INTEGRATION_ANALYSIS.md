### 6.1 Build Configuration

```
frontend/dist/          # Generated by: npm run build
├── index.html

│   ├── index-[hash].js
```

#### Build Commands

```bash
# Development
pnpm run dev              # Start both frontend + backend with hot reload
npm run frontend:dev      # Frontend only (port 3000)
npm run backend:dev       # Backend only (Rust server)

# Production build
cd frontend && npm run build   # Frontend → frontend/dist/
./local-build.sh               # Full build with Rust binaries
./build-npm-package.sh        # Create NPM package

# Testing & validation
npm run check             # TypeScript + Rust checks
npm run lint              # ESLint + Clippy
npm run format            # Prettier + cargo fmt
npm run generate-types    # Generate TS types from Rust
```

#### Customizing Build Output Path

**✅ YES - Easily Customizable**

The build output path can be configured in `frontend/vite.config.ts` by adding:

```typescript
export default defineConfig({
  build: {
    outDir: '../efficiency-tools/src/.../ui/build/',
    sourcemap: true
  },
  // ... rest of config
});
```

Vite's `build.outDir` accepts any relative or absolute path.

**1. API Layer Adapter (50-100 lines)**

Create `frontend/src/adapters/ApiAdapter.ts`:

```typescript
// Intercept/proxy API calls to efficiency-tools backend
export class ApiAdapter {
  private baseUrl: string;

  constructor(baseUrl: string) {
    this.baseUrl = baseUrl;
  }

  // Map Vibe Kanban API calls to efficiency-tools endpoints
  async getTasks(projectId: string) {
    // Map to: GET /api/speckit/tests
    const response = await fetch(`${this.baseUrl}/api/speckit/tests?suite=${projectId}`);
    return this.mapTestsToTasks(await response.json());
  }

  async createTask(task: Task) {
    // Map to: POST /api/speckit/tests
    const specKitTest = this.mapTaskToTest(task);
    return await fetch(`${this.baseUrl}/api/speckit/tests`, {
      method: 'POST',
      body: JSON.stringify(specKitTest)
    });
  }

  // ... more API mapping methods
}
```

### 8.2 Integration Strategy Recommendation

#### Option A: Fork + Adapter Layer ⭐ RECOMMENDED

**Complexity:** ⭐⭐⭐ (Medium)
**Maintenance:** Easy (merge upstream changes periodically)
**Separation:** Excellent
**Control:** Full control over customization

**Steps:**

1. **Fork the repository**
   ```bash
   git clone https://github.com/BloopAI/vibe-kanban.git my-vibe-kanban
   cd my-vibe-kanban
   git remote add upstream https://github.com/BloopAI/vibe-kanban.git
   ```

2. **Create adapter directory**
   ```bash
   mkdir -p frontend/src/adapters
   ```

3. **Implement adapters**
   - `SpecKitAdapter.ts` - Data model translation
   - `ApiAdapter.ts` - API endpoint mapping
   - `ConfigAdapter.ts` - Configuration management

4. **Modify build configuration**
   - Update `frontend/vite.config.ts` to output to your desired path
   - Add environment variables for your API endpoints

5. **Build and test**
   ```bash
   cd frontend
   npm run build  # Outputs to your configured path
   ```

6. **Integrate into your project**
   - Built files are now in your efficiency-tools directory
   - Serve via your backend or as static files

7. **Maintain fork**
   ```bash
   # Periodically sync with upstream
   git fetch upstream
   git merge upstream/main
   # Resolve any conflicts in your adapter layer (rare)
   ```

**Pros:**
- ✅ Full control over all code
- ✅ Can customize deeply if needed
- ✅ Adapter layer keeps integration clean
- ✅ Easy to track your changes (git diff)

**Cons:**
- ⚠️ Need to periodically merge upstream changes
- ⚠️ Slightly more complex initial setup

**Separation:** Excellent

**Pros:**
- ✅ Simplest maintenance (just `npm update`)

- ✅ All adapter code in your repo

**Cons:**
- ⚠️ Limited to exported components/APIs
- ⚠️ Cannot customize Vibe Kanban internals
- ⚠️ May not expose all features you need
